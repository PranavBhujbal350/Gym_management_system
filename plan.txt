# Project: Gym Management System — Full Stack Web Application

Act as a senior full-stack developer and guide me through building a complete, professional Gym Management System from scratch. I am a student building this as a college project, so the code must be understandable, properly structured, fully functional, and easy to explain in a viva.

## 1. Technology stack

Use the following technologies:

- **Frontend:** HTML5, CSS3, JavaScript, Bootstrap 5
- **UI rendering:** Flask templates using Jinja2
- **Backend:** Python Flask
- **Database:** MySQL, managed using MySQL Workbench
- **Database connector:** `mysql-connector-python`
- **Authentication:** Flask sessions and Werkzeug password hashing
- **API testing:** Postman
- **Version control:** Git and GitHub
- **Development environment:** VS Code

Do not introduce React, Node.js, MongoDB, or other frameworks unless I explicitly ask.

## 2. Main project objective

Create a complete Gym Management System that allows gym administrators to manage members, trainers, memberships, payments, attendance, workout plans, and other gym operations through a professional web interface.

The project must have a working connection between the frontend, Flask backend, and MySQL database. All important forms, buttons, tables, filters, and actions must work with actual database records, not hardcoded sample data.

## 4. MySQL database

Create a complete SQL schema named `gym_management`.

Include suitable tables such as:

1. `users` — authentication, name, email, phone, password hash, role, account status
2. `members` — member-specific details and registration date
3. `trainers` — trainer profiles, specialization, experience, and availability
4. `membership_plans` — plan name, duration, price, and description
5. `member_memberships` — assigned plan, start date, end date, and status
6. `payments` — member, membership, amount, payment date, method, transaction reference, and status
7. `attendance` — member, check-in time, check-out time, and attendance date
8. `workout_plans` — plan name, description, difficulty, and creator
9. `member_workouts` — member, assigned workout plan, trainer, and assignment date
10. `workout_exercises` — exercise name, sets, repetitions, duration, and instructions
11. `trainer_assignments` — trainer-to-member assignments, if needed

Use appropriate primary keys, foreign keys, unique constraints, indexes, data types, and referential integrity.

Avoid storing duplicate information unnecessarily. Explain the relationships between tables and provide an ER diagram or Mermaid ER diagram.

Provide a complete SQL script that I can paste into MySQL Workbench and execute. Also provide a few optional sample records for testing.

Never store plaintext passwords. Hash passwords with Werkzeug.

Do not claim that a payment was actually processed through a payment gateway. For this college project, implement a clearly labelled manual payment-recording or simulated-payment workflow unless I explicitly request a real payment integration.
